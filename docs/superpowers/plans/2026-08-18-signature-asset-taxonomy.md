# Signature Asset Taxonomy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Leo Ferraz signature asset and component names describe their actual visual roles without changing approved geometry, color, typography, or composition.

**Architecture:** The generator becomes the source of truth for five explicit signature roles: primary lockup, wordmark-only, descriptor lockup, institutional lockup, and symbol. Existing ambiguous filenames remain generated compatibility aliases until consumers are migrated. `BrandSignature` exposes semantic variants and the site keeps using approved exported SVG files rather than redrawing the mark.

**Tech Stack:** Node.js ESM, Astro 7.2.2, SVG outlines generated by `scripts/build-brand-assets.mjs`, Markdown/Obsidian notes, npm validation and Astro build.

## Global Constraints

- Preserve `Constructed LF Lockup`, `Leo Ferraz`, `Building with AI`, and `AI-Native Product Lab` exactly.
- Preserve IBM Plex Sans outlined geometry, `#F3F6FA`, `#4DA3FF`, `#86C5FF`, safe zones, and approved dimensions where the visual is unchanged.
- Do not edit unrelated homepage work already present in the working tree.
- Do not delete compatibility aliases in this pass.
- Do not add dependencies or client-side JavaScript.
- Stage only intentional taxonomy, generated asset, documentation, and vault files.
- Commit on `main` with `docs: clarify signature asset taxonomy` and push to `origin/main` after validation.
